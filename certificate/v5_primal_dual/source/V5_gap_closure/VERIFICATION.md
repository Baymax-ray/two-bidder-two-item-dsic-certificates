# V5 verification boundary

From this V5 directory, run:

    python -B -X utf8 verifier/run_all.py

Default execution recomputes and compares evidence without writing it. The receipt writer is explicitly requested with:

    python -B -X utf8 verifier/run_all.py --record

The recorded run covers:

1. Complete continuous splice replay: all 294 roots and 12,294 leaves, outward arithmetic, source hashes, and net upper-value assembly.
2. Exact rational BB replay: all 64 selected boxes, source reconstruction, first-event inequalities, disjointness, and full envelope gain.
3. Face-integral replay: 296 resolved strips, 15 whole-strip enclosures, all moment coefficients and approximation allowances.
4. Complete primal arithmetic: degree-five revenue, derivative, tie-complete implementation checks and whole-box ownership switch.
5. Independent primal check: separate sparse-polynomial menu and lottery moments, face multiplicities, interval coverage, revenue assembly, and ownership margins.
6. Exact phase assembly and preservation of all 4,278 predecessor identities.
7. Two independent upper audits: a fresh primary splice replay with exact selected Bernstein/averaging cross-checks, and an independent BB field/envelope algebra audit.
8. Rejection of optimized Python for all eight entry points; compilation without writing bytecode; unchanged accepted inputs across replay.

All eight normal entry points are read-only. The independent upper audit scripts live under discovery for provenance, but their assertions are part of acceptance. Other discovery scripts and the long, inconclusive QQ curl verifier are excluded from the accepted runner. No floating discovery estimate is counted as a gain.

The implementation uses Python 3.10+ and NumPy; the exact polynomial checks use the standard library. Interval proofs explicitly trust IEEE-754 binary64 basic operations and NumPy nextafter. Rational inputs are bracketed, all operations affecting acceptance expand outward, and final dyadic contributions are accumulated exactly. Exact Fraction comparisons cover the BB and face-integral acceptance.

The written universal DSIC proof, integration-by-parts identities, source branch coverage, and inherited theorems remain mathematical dependencies. Finite report/deviation tests are implementation checks, not a substitute for all-real DSIC and feasibility. Inherited large integration certificates and predecessor proofs were hash-checked and consumed through their certified endpoints; the runner does not repeat every historical expensive search or reprove every inherited theorem.

The receipt records actual subprocess status and timing; no claimed PASS is inferred merely from the presence of an old JSON file. SHA256SUMS establishes source identity and stable-file coverage, not theorem correctness. The new manifest and outer auction manifest are checked separately after the final report is written.
